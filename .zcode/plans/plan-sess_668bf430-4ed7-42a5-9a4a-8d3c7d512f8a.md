# S7 遗留清零 — 完整实施方案（批次 C：WS1→WS4）

四个工作流按依赖排序：**WS1 angle 删除**（纯减法，先腾空间）→ **WS2 plan_checkpoint 连续执行**（two-phase 退役为高风险例外）→ **WS3 PostToolUse(SendMessage) 计划回执捕获**（WS2 的观察路径，需先反转 migration 禁令）→ **WS4 ReviewPlan 增值闭环**（受控 revision、Claim 草稿+求差、cold-start 写面、capture buffer）。每个 WS 独立验证收口。

调查已确认的两个关键边界（方案如实对待）：
- **平台 payload 限制**：PreToolUse/PostToolUse 的子代理 payload 当前不带 `agent_id`（只有 `tool_input.subagent_type/team_name`）。识别策略 = payload agent_id → teammate_name 匹配 entities.agents → 唯一活跃 reading 态 agent 兜底；识别失败则观察静默跳过（不 block、不写）。
- **浏览器级 encounter 自动采集属产品侧**：harness 提供 capture buffer + 脱敏 gate + submit 绑定（WS4d），蓝图审计明确此边界。

## WS4 — ReviewPlan 增值闭环

**a. 受控 revision**（`runtime review-plan revise --file v2.json --source-ref <ref> --affected-surface <path>`）：
- 前置：plan 状态 ∈ running/cannot_clean/discovery_draining；本轮 revision 次数 0（`plan.revision` 1→2 仅一次）
- diff 约束：v1 中不触碰 affected_surface 的 claim 在 v2 原样保留；新增/修改的 claim 必须 source_refs 含 --source-ref 且 target 落在 affected_surface 下；assignment 分割仍精确
- CAS：钉 v2 文件、revision+1、受影响 claim→planned / assignment→planned、**已消费且被修改的 result evidence 标 invalid**（invalidation_reason=plan_revision）

**b. Claim 草稿 + coverage 求差**（`loop-harness review-plan draft --root . [--out file]`，只读生成器）：
- 读当前 generation 的 task documents + completion envelopes（changed_paths/checks）+ bound REQ → 输出 plan scaffold：每 TASK 生成 DV 符合性 claim 桩 + QA 静态 focus 桩 + E2E 状态评估桩 + TODO 标注
- 注册时强化 `ValidatePlan`：当前 generation 每个 TASK id 必须出现在 ≥1 claim.source_refs（block）；CASE/PATH 覆盖在 draft 输出中标注缺口（warn，不 block——scenario 资产完备度属 Planner 判断）

**c. E2E cold-start 写面**：
- `review-plan` 注册时 cold_start：workspace 必须为 repo 内专用新目录 `e2e-workspace/<plan-id>/`，创建之
- `review-result submit` 对带 workspace 的 e2e assignment：计算 workspace digest（sha256 over sorted 相对路径:文件哈希行）与 `result.verification_artifact_digest` 比对，不符拒绝；digest 记入 plan pointer
- seal/clean 收口时重算 workspace digest，与已消费 result 绑定的 digest 不一致 → 拒绝出口（闭环失效，不重跑）

**d. capture buffer**：
- `loop-harness capture step --assignment <id> --action <s> --observed <s> [--evidence <ref>] [--sequence n]`：追加 `.claude/evidence/<rt>/g<gen>/captures/<assignment>/steps.jsonl`
- 脱敏 gate：内容命中 password/token/secret/api-key/bearer 值模式 → 拒绝写入（exit 1 指明字段）
- `review-result submit --captures <dir>`：对 encounter.timeline 为空的 finding 自动并入 steps.jsonl（step-bound evidence 校验随之生效）
- 浏览器/runner 注入式采集 = 产品侧，蓝图审计注明边界

**测试**：revise 全约束矩阵（无源拒绝/二次拒绝/触碰外 claim 变更拒绝/已消费失效）、draft 生成快照、TASK 覆盖 block、workspace digest 比对与收口失效、capture 脱敏与并入。
