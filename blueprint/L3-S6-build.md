# L3-S6 — 构建（Build）

> 层：第三层 ｜ 上游：L2 §S6 ｜ 版本 v3.0.0（叙事版：目标→工具→选择→编排→效果）

## 1. 要实现什么

把一批原子锁定的任务，变成**通过自身判据的实现**和**可被复验的诚实报告**。

- 进入时：S5 锁定的任务批次（每任务带读序、允许/禁止路径、收尾契约判据）。
- 出去时：每个任务有一份完成报告——判据逐条兑现（含先红后绿证据）、改动路径清单、三态结论——且 S7 能拿着报告逐条复验。
- 衡量：**报告里说的每一句话，S7 都能复跑验证**。做不到这一点的报告等于没交。

## 2. 手头有什么（现有机制，不新造）

| 机制 | 它能干什么 |
|:--|:--|
| PreToolUse hook | 工具调用瞬间执法（未激活写拦截、越界写拦截）+ 质量门评估 + 满足即自动迁移状态 |
| SubagentStart / SubagentStop hook | 派发瞬间提醒预检 / 收队时强制完成报告+worktree 集成清单 |
| PreCompact + SessionStart hook | 任意时刻崩溃后，从权威状态重入座 |
| harness `team launch` | 按团队清单生成指纹化读回信封 |
| harness `runtime agent-event` | 读回提交→批准→激活三事件——**授权在册的唯一登记处** |
| harness 质量门 + 自动迁移（TR-006） | 批次齐了自动进 S7，无需人拨表 |
| TASK 模板 / 完成报告模板 | 收尾契约字段 / 三态+偏差段的报告结构——模板字段即逼问 |
| 角色定义（frontend/backend/test-builder） | 每类构建者的工具集与写路径上限 |
| skill（two-phase-activation / team-planning / bug-resolution） | 两阶段流程方法 / 组队计算 / 缺陷路由纪律 |

## 3. 选了什么、为什么（含否决）

| 子问题 | 选用 | 备选与否决理由（减法） |
|:--|:--|:--|
| 怎么保证理解先于动手 | `two-phase-activation`（读回-批准-激活）+ `runtime agent-event` 在册 | 否决"派发即信任"——理解错误的返工比读回贵一个数量级 |
| 怎么限制写权限 | 激活面=交集求值（harness）+ PreToolUse 实时拦截 | 否决"独立监工 agent 巡查"——常驻 agent 复杂度高、收益与 hook 拦截重合，删 |
| 怎么保证报告诚实 | 完成报告模板（三态/偏差段/判据映射）+ SubagentStop 收报告检查清单 + S7 复跑 | 否决"实时监控 agent 行为"——判断成本高、误伤大；事后复验更便宜且确定 |
| 怎么保证"完成"可判定 | TASK 模板收尾契约字段（声明判据）+ harness 校验（证据存在） | 判据 id 从 S4 一路贯到 S7，不另造核对语言 |
| 怎么防顺手修 | harness 事后 git 差集（被动审计）+ bug-resolution skill 指引 | 否决"实时行为审查"——事后差集零成本且不可抵赖，足够 |
| 怎么推进到 S7 | PreToolUse → GATE 求值 → TR-006 自动迁移 | 否决人工确认节点——门是机械求值，加人只加时滞 |

## 4. 怎么编排（时间线讲完一件事）

1. **组队**：`team-planning` skill 按任务的写路径归属算任命（TASK 模板的职责/路径/判据字段就是任务简报的底稿）；PreToolUse 派发预检在此刻提醒（单人 vs 团队？角色模板？worktree？team_name？）。
2. **读回**：`team launch` 给每个任命发指纹化读回信封；构建者读全链（任务→契约→需求→规则）并核对指纹；主会话审其理解——批准前，PreToolUse 拦一切写。
3. **激活**：`runtime agent-event` 登记激活，授权面=交集；从此域内写放行、域外写拦截，激活事实可审计。
4. **实现**：构建者先跑收尾契约中"修复前失败"类判据留存红色输出，再实现到全绿——判据证据（命令+退出码+输出留存）随做随集。
5. **报告**：按完成报告模板交三态结论；SubagentStop 收报告并给 worktree→develop 集成清单；过程中发现的缺陷只进 findings 段，不修。
6. **推进**：主会话汇集报告；下一次工具调用时 PreToolUse 评估 GATE-BUILDER-BATCH-READY（每任务有报告+判据映射+改动在域内），满足即 TR-006 自动进 S7。
7. **恢复**（任意时刻）：PreCompact 存检查点 → SessionStart 从权威状态重入座，构建进度不依赖记忆。

## 5. 期望效果

走完本 stage：

- **可复验**：每份报告的判据 id 直通 S7 复跑，报告与事实的缝隙会在 S7 被机械揭穿；
- **结构性防住**：未授权写（激活前拦）、越界写（实时拦+事后差集）、报告美化（三态+偏差段+复验）、顺手修（差集+findings 路由）、"基本完成"（模板无处下笔）；
- **无人拨表**：批次齐了自动进验证轮；人只在受阻清单非空时出现；
- **交给 S7**：报告+判据证据+改动路径清单——S7 机械预检与抽查的直接输入。
