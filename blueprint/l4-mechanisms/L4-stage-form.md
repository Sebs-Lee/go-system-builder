# L4 — 阶段答卷

> 层：第四层｜机制域：每个阶段一份答卷，判断或状态变更如何进入既有门禁
>
> 上游：L1 D3/D4/D5 与公理二、公理五；L2 各阶段出口；[L4 运行时控制面](L4-runtime-control-plane.md)；[L4 revision](L4-revision-usage.md)；命令链、对外名字、重复载体和占位符的收敛见 [L4 手续收敛](L4-procedure-reduction.md)
>
> 状态：v0.5.0 设计。未实现。本文不新增状态机。卷子写完不等于通过。

## 1. 机制

一个需求的每个阶段只有一份答卷。进入该阶段时，Hook 生成这一份，并把路径放进 `next`。模板在 Runtime 内部，Agent 不复制外部样例。

这份文件只有两种内容：

- **要判断。** 空位已经摆好。工作做完后，Agent 把答案写入这个文件，写入就是交卷。
- **只记状态。** 本阶段能否前进只取决于 REQ 或文件状态。Hook 在状态成立时把变更写入同一份文件，里面没有空题，Agent 不用填。

然后走同一条路：Hook 按文件路径计算指纹、记下内容，再跑这个阶段原来的门。门通过才进入下一阶段，并生成下一份卷。门不过就停住，回执说明缺什么，要改的仍是这一份。

Agent 不填写哈希、代数、身份和事件名，也不另跑提交命令。

## 2. 文件

目录是 `.claude/forms/`。文件名只用于定位，不标注待填或已完成。当前阶段以 Hook 的提示为准。过门和重做都不改名，重做覆盖这一份。

```text
.claude/forms/REQ-<req-id>-S<nn>-<slug>.json
```

`S<nn>` 用两位，使 `S05` 排在 `S10` 前面。`ls .claude/forms` 时，同一需求按阶段号排在一起。

| 阶段 | 文件 |
|:--|:--|
| S00 需求 | `REQ-006-S00-requirement.json` |
| S01 绑定 | `REQ-006-S01-bind.json` |
| S02 设计 | `REQ-006-S02-design.json` |
| S03 合同 | `REQ-006-S03-contracts.json` |
| S04 任务 | `REQ-006-S04-tasks.json` |
| S05 文档审查 | `REQ-006-S05-document-verification.json` |
| S06 构建 | `REQ-006-S06-build.json` |
| S07 验证 | `REQ-006-S07-verification.json` |
| S08 调查 | `REQ-006-S08-investigation.json` |
| S09 修复 | `REQ-006-S09-repair.json` |
| S10 验收 | `REQ-006-S10-acceptance.json` |
| S11 发布 | `REQ-006-S11-release.json` |

同一阶段若有多名审查者或多个任务，它们是这一份里的不同空位，不是第二份文件。

## 3. 发卷时写什么

进入阶段时 Hook 先看原有的门能否只凭当前 REQ 状态和文件状态通过。

能通过：把状态、变更路径和 Hook 算出的 sha256 写入该文件，不留空题，并继续第 4 节的过门。S00、S01、S11 属于这一类；S02、S03、S04、S09 在状态已经满足时也属于这一类。

不能只凭状态通过：写入空位，并提示：

```text
本阶段的卷子在 .claude/forms/REQ-006-S05-document-verification.json
工作做完后，把答案填进这个文件。
```

S05 的空位是两块，路径只有一个。Hook 告诉每名审查者填自己那一块：

```json
{
  "DV-SPEC": {
    "conclusion": null,
    "findings": [{ "path": "", "expected": "", "observed": "" }]
  },
  "DV-TASK": {
    "conclusion": null,
    "findings": [{ "path": "", "expected": "", "observed": "" }]
  }
}
```

S06 的各任务、S08 的各 Case 同样放在各自那一份里面。可选项和要先阅读的路径写在 `next` 里，不写进卷子。

`pass` 可以带着空白 finding。`fix_required` 或 `req_change_required` 若没有 path 与 observed，这次写入无效。任一块仍是 `null`，门不过，回执仍指向这一个文件。

## 4. 过门

触发只有两种：Agent 写入了带空位的卷，或 REQ / 文件状态发生了该阶段认可的变更。

Hook 接着做三步：

1. 读取卷里的判断，以及判断和状态变更里的路径。路径读不到则拒绝，并指出路径。卷上若有哈希字段，忽略。
2. 用路径的当前字节计算 sha256，连同身份、代数、由结论推导的事件，写入既有证据索引。再次写入用新字节覆盖同一登记。
3. 跑该阶段原来的门。通过才进入下一阶段并生成下一份卷。未通过则停留，回执写明缺的检查或空位。

填完空位本身不构成通过。双人结论都在、路径与当前登记一致、不通过时有可定位的 finding、需求变更停在人闸、实现差异落在任务范围内，这些检查仍由原来的门负责。

## 5. 落地与判据

先做 S05 这一份双空位卷，以及 S01、S04 这种可由状态直接写入的卷。再覆盖其余阶段。最后去掉 Skill、角色卡和外部模板里让 Agent 手抄信封的入口。

判据有三条。每个阶段在 `.claude/forms/` 里只有一个文件，文件名不因过门而改变。`next` 给出的路径就是这个文件。不需要判断时，文件里没有空题；需要判断时，漏掉的空位会挡住过门，且回执不指向第二份卷。
